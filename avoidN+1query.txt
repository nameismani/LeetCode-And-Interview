Sure! Let’s look at the **N+1 problem in plain SQL** and how to fix it.

---

### **Scenario**

We have two tables:

**users**

| id | name  |
| -- | ----- |
| 1  | Alice |
| 2  | Bob   |

**posts**

| id | user_id | title        |
| -- | ------- | ------------ |
| 1  | 1       | Alice Post 1 |
| 2  | 1       | Alice Post 2 |
| 3  | 2       | Bob Post 1   |

---

### **N+1 Query Example**

Step 1: Get all users

```sql
SELECT * FROM users;
```

Step 2: For each user, get their posts

```sql
SELECT * FROM posts WHERE user_id = 1;
SELECT * FROM posts WHERE user_id = 2;
```

If there are **N users**, you do **1 query for users + N queries for posts = N+1 queries**.
This is inefficient if N is large.

---

### **Fix: Use JOIN to get everything in one query**

```sql
SELECT u.id AS user_id, u.name AS user_name, p.id AS post_id, p.title AS post_title
FROM users u
LEFT JOIN posts p ON u.id = p.user_id;
```

Result:

| user_id | user_name | post_id | post_title   |
| ------- | --------- | ------- | ------------ |
| 1       | Alice     | 1       | Alice Post 1 |
| 1       | Alice     | 2       | Alice Post 2 |
| 2       | Bob       | 3       | Bob Post 1   |

✅ **One query** fetches users and all their posts — no N+1 problem.

## **1️⃣ Normalization (Good for reducing redundancy)**

### **Tables**

**1. Customers**

```sql
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100)
);
```

**2. Products**

```sql
CREATE TABLE Products (
    product_id INT PRIMARY KEY,
    name VARCHAR(100),
    price DECIMAL(10,2)
);
```

**3. Orders**

```sql
CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);
```

**4. OrderItems**

```sql
CREATE TABLE OrderItems (
    order_item_id INT PRIMARY KEY,
    order_id INT,
    product_id INT,
    quantity INT,
    FOREIGN KEY (order_id) REFERENCES Orders(order_id),
    FOREIGN KEY (product_id) REFERENCES Products(product_id)
);
```

### **Insert sample data**

```sql
-- Customers
INSERT INTO Customers VALUES (1, 'Alice', 'alice@example.com');
INSERT INTO Customers VALUES (2, 'Bob', 'bob@example.com');

-- Products
INSERT INTO Products VALUES (101, 'Laptop', 1200.00);
INSERT INTO Products VALUES (102, 'Mouse', 25.00);

-- Orders
INSERT INTO Orders VALUES (1001, 1, '2026-04-08');
INSERT INTO Orders VALUES (1002, 2, '2026-04-07');

-- OrderItems
INSERT INTO OrderItems VALUES (1, 1001, 101, 1);  -- Alice bought 1 Laptop
INSERT INTO OrderItems VALUES (2, 1001, 102, 2);  -- Alice bought 2 Mice
INSERT INTO OrderItems VALUES (3, 1002, 102, 1);  -- Bob bought 1 Mouse
```

### **Query: Get all orders with customer and product info**

```sql
SELECT o.order_id, c.name AS customer_name, p.name AS product_name, oi.quantity
FROM Orders o
JOIN Customers c ON o.customer_id = c.customer_id
JOIN OrderItems oi ON o.order_id = oi.order_id
JOIN Products p ON oi.product_id = p.product_id;
```

**Output:**

| order_id | customer_name | product_name | quantity |
| -------- | ------------- | ------------ | -------- |
| 1001     | Alice         | Laptop       | 1        |
| 1001     | Alice         | Mouse        | 2        |
| 1002     | Bob           | Mouse        | 1        |

✅ **No redundancy**, everything is normalized.

## **2️⃣ Denormalization (Combine tables to reduce joins)**

Sometimes, for performance or reporting, we **denormalize** to reduce joins. For example, store **customer and product info directly in the order items table**.

```sql
CREATE TABLE OrderItems_Denormalized (
    order_item_id INT PRIMARY KEY,
    order_id INT,
    customer_name VARCHAR(100),
    product_name VARCHAR(100),
    quantity INT,
    price DECIMAL(10,2),
    order_date DATE
);
```

### **Insert data (flattened)**

```sql
INSERT INTO OrderItems_Denormalized VALUES
(1, 1001, 'Alice', 'Laptop', 1, 1200.00, '2026-04-08'),
(2, 1001, 'Alice', 'Mouse', 2, 25.00, '2026-04-08'),
(3, 1002, 'Bob', 'Mouse', 1, 25.00, '2026-04-07');
```

### **Query: Get all orders**

```sql
SELECT * FROM OrderItems_Denormalized;
```

**Output:**

| order_item_id | order_id | customer_name | product_name | quantity | price   | order_date |
| ------------- | -------- | ------------- | ------------ | -------- | ------- | ---------- |
| 1             | 1001     | Alice         | Laptop       | 1        | 1200.00 | 2026-04-08 |
| 2             | 1001     | Alice         | Mouse        | 2        | 25.00   | 2026-04-08 |
| 3             | 1002     | Bob           | Mouse        | 1        | 25.00   | 2026-04-07 |

✅ **No joins required**. Easy to query, but **data is duplicated** (Alice appears twice, product info repeated).

---

### **Summary Table**

| Aspect                          | Normalized                                  | Denormalized                    |
| ------------------------------- | ------------------------------------------- | ------------------------------- |
| Data redundancy                 | Low                                         | High                            |
| Query performance for reporting | Slower (needs joins)                        | Faster (flattened)              |
| Storage                         | Efficient                                   | Less efficient                  |
| Flexibility                     | High (easy to update product/customer info) | Low (hard to update duplicates) |
